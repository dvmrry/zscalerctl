# zscalerctl v1.0.0

The first stable release. zscalerctl reads ZIA, ZPA, ZTW, ZCC, ZIdentity and
ZDX configuration and never changes the tenant. From 1.0 the command line,
output schemas and exit codes follow semantic versioning; see
[VERSIONING.md](https://github.com/dvmrry/zscalerctl/blob/v1.0.0/docs/VERSIONING.md).

## Upgrading from v0.68.1

### Install

The Go module path is now `zscalerctl`, so
`go install github.com/dvmrry/zscalerctl@latest` stays at v0.68.1. Install
from the release archives, which come with signed checksums and build
provenance, or clone and build; see
[INSTALL.md](https://github.com/dvmrry/zscalerctl/blob/v1.0.0/docs/INSTALL.md).

### Breaking changes

- `dump --out DIR` is now `dump --output DIR`, the global flag, which may come
  before or after the command. `--out` is gone. `--force` still guards
  replacing an earlier dump.
- A run that hits its deadline exits `5` with kind `deadline_exceeded`;
  v0.68.1 exited `1` with kind `internal`. A canceled run still exits `1`, now
  with kind `canceled`.
- The stderr error envelope is `zscalerctl.error.v2`. It adds `reason`,
  `retryable` and `status`, and `kind` gains the two values above; the other
  v1 fields and kinds are unchanged. Partial-dump error records are
  `zscalerctl.dump.error.v2`.
- `secret` now means credential material only. 447 fields that never rendered,
  mostly ids, settings and structure, are reclassified and now render in the
  modes their new class allows. Counting fields on resources that existed in
  v0.68.1, `share` now renders 706 more and `paranoid` 294 more. All of them
  are tenant configuration or operational metadata; no sensitive identifier
  or free-text field joins `share` or `paranoid`. If you rely on those modes
  to limit what you paste, check the Modes column in
  [RESOURCES.md](https://github.com/dvmrry/zscalerctl/blob/v1.0.0/docs/RESOURCES.md)
  for the resources you share.
- 37 catalog paths that no reader ever emitted are gone: `parent` under id and
  name references, zcc/company-info `webAppConfig` and zia/ips-signature-rules
  `ruleText`. None of them rendered, but `--fields` naming one now exits `2`
  as an unknown field instead of returning nothing.

### Unchanged

- The default redaction mode is still `standard`; `share` and `paranoid` are
  opt-in.
- Apart from the deadline above, exit codes behave as before. The v0.68.1 docs
  said rejected credentials exit `3` and an unentitled resource exits `4`;
  both already exited `5`, which 1.0 documents, with the cause in the
  envelope's `reason`.
- Dump manifests (`zscalerctl.dump.manifest.v2`), diff reports
  (`zscalerctl.diff.v1`) and redaction reports (`zscalerctl.redaction_report.v1`)
  keep their versions.
- No resource was removed, and no field v0.68.1 rendered in a mode has stopped
  rendering in it.

## New

- 47 more resources, 212 in all: 28 ZPA, 12 ZIA, 5 ZDX reports (a new
  product), 1 ZCC and 1 ZIdentity. Every field lists its JSON type.
- `--limit` and `--offset` return a bounded JSON page with a `pagination`
  object; `--count-by` counts records by fields instead of listing them.
- `--from-dump` reads resources from a saved sanitized dump instead of the API.
- `--fields` and `--filter` take dotted paths such as `groups.id`.
- `refs` finds the records that reference an object, and `refs check` lists
  reference ids that are not in the lists read.
- `schema describe` and `schema references` describe one resource's fields and
  links; `introspect` prints a machine-readable map of every command, flag and
  resource, and `machine manifest` the machine capability manifest.
- The error envelope's `reason` names the cause: `credentials_rejected`,
  `forbidden`, `not_subscribed`, `rate_limited`, `timeout`,
  `pagination_incomplete` and more.
- A list zscalerctl cannot prove complete is refused with
  `pagination_incomplete`, and the message names the check that failed.
- An unknown resource name suggests up to three catalog names
  (`did you mean zpa/access-policy-rules?`).
- Table and pretty output redact exactly what JSON output redacts.

## Known issues

These are API behaviours seen on live tenants, not zscalerctl defects.

- zia/intermediate-ca-certificates: on some tenants page 2 returns a record
  from page 1 again, so the list fails with `pagination_incomplete` (exit `5`).
- zidentity/resource-servers: the API can report a `resultsTotal` larger than
  the records it returns, with no next link, so the list fails with
  `pagination_incomplete`.
- zia/cloud-app-instances: some tenants answer HTTP 400 (`client_error`,
  exit `5`) even at the documented page size, most likely because the tenant
  does not have the feature.
